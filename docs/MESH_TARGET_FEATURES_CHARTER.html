Mesh Target Features and Technical Charter

Owner review draft · October 1, 2026 · Prepared by Codex

Purpose and ownership

Mesh connects an owner to independently running agents. The target is a usable fleet and software factory control surface while runtime, memory, credentials and durable files remain on the owner’s machine. This is a feature charter for Edwin’s review, authored by Codex on October 1, 2026. It describes product targets and the current implementation boundary; it does not certify a production release.

Agent enrollment and identity

Target: signed enrollment, real owner authentication, named agent selection, explicit host-to-runtime bindings, shared owner access, reconnect and removal without deleting the underlying agent. Current source provides enrollment and per-agent management paths. Identity discovery is distinct from cryptographic enrollment; local authenticated host access must be labeled accurately.

Fleet visibility and communication

Target: each agent shows availability, model, transport, active work, progress and last result; owners can chat with the exact selected role, choose permitted models and inspect scoped task or terminal snapshots. Keep channels separate. Wake, sleep, recovery and new-conversation controls must respect retained work and shared hardware admission. A successful reply is distinct from a completed task or published deliverable.

Factory office and coordination

Target: a persistent office view with a Director and specialist agents, reviewable missions, dependency tracking, approvals, priorities, mailbox handoffs, bounded native inference and optional CrewAI or OpenHands execution. Relationships and activity must follow evidence rather than animation. Framework execution requires a configured runtime and workspace; configuration availability is not execution qualification.

Per agent Specklet task boards

Target: Use Specklet in the fleet and Factory inspector; a dedicated Task Board for each enrollment; resume the local file or update it through an uploaded or editable JSON workspace. Keep scope, notes, priority, order and status editable. Save every supported agent-tool and office status mutation atomically. Switch-off freezes automatic tracking while preserving owner review, edits and export. The local file itself and every download use Specklet browser-workspace version 2, compatible with its Settings importer. Each agent receives only its own enabled boards.

Specklet round trips and history

Target: the owner exports an agent board to specklet.progretech.com for historical review and rearrangement, exports changes there and uploads them back to Mesh. Stable IDs preserve task identity and revision checks prevent stale uploads overwriting newer changes. Specklet currently merges imports without replacing matching browser IDs; repeated snapshots require separate or deliberately reconciled browser workspaces. The host retains 250 recent board mutations. Owner-exported snapshots supply long-term history. Full website embedding and automatic cloud account synchronization are outside this implementation.

Memory and context

Target: MemPalace remains the durable context, evidence and teaching system with runtime-bound authorship and private-role boundaries. Specklet tracks task scope and status. Task updates never replace memory writeback or imply that every memory is a task. An agent may reference memory from a task while keeping the two lifecycles independent. Owner-authorized shared project memory search remains separately controlled.

Files and deliverables

Target: bounded attachment upload, byte-count and hash verification, safe host inbox references, published artifact browsing, downloads and conditional handoffs after a new artifact appears. Preserve provenance and distinguish input attachments, published output and completed missions. Files must not execute merely because they are uploaded or previewed.

Routing and deployment

Target: same-LAN first, direct peer communication when feasible and optional authenticated relay. The cloud supplies control, identity and ephemeral transport, not a replacement agent runtime or durable operational archive. Hosted and local Mesh should share source, templates and assets, version identifiers and acceptance criteria. Standalone platform installers need their own native builds; updating a local web service is a separate release action.

Privacy and control boundaries

Target: exact agent binding, owner-only access, same-origin mutations, credentials remaining local, no unrestricted remote shell and no automatic replay after uncertain execution. Render task and memory text as data. Board text does not authorize publishing, delegation or external messaging. Imports cannot turn tracking on or change host permissions.

Acceptance criteria for this change

Check default-off and per-agent isolation; enable, restart, disable during work and resume; preserve the disabled JSON against automatic writes; owner edits while off; actual Specklet IndexedDB import and export back to Mesh; stable IDs and order; stale-revision rejection; malformed upload rejection; atomic writes and concurrent updates; safe rendering; native tool identity and error reporting; office namespace isolation; full Mesh regressions. Fixture acceptance and live owner/model acceptance are distinct evidence.

Current limits and review priorities

This implementation uses a Mesh-native Task Board sharing Specklet’s JSON format rather than embedding the whole Specklet application. Native workday snapshots are observed every two seconds and can omit intermediate states; supported direct tool and office writes persist synchronously. Model adherence to task-update instructions still needs live acceptance. Initial limits are 500 tasks, 256 KiB workspace content and a 512 KiB import payload. Production deployment, local activation and installed agent adapter qualification must be recorded before claiming the feature is live. Review priorities: approve this scope, decide whether Specklet should later support replace-by-ID imports, and whether event-driven native workday tracking is needed.
