# Agent Specklet task boards

Each enrolled OpenClaw agent has a **Use Specklet** toggle in the Mesh fleet and Factory inspector, and its own **Task Board** page. Its local board defaults off. Enable it to resume the saved board, or use **Update agent Specklet** to import a Specklet Settings export or editable workspace JSON. Import replaces this board under a revision check; it does not change another agent or turn tracking on. Owner edits and exports remain available while tracking is off.

The authoritative file is `~/.progretech-mesh/agent-profiles/<enrollment>.specklet.json`. It is itself a Specklet browser-workspace version 2 JSON file. Mesh host settings, revision and recent transition history are an extension under `mesh`; imported extensions never grant permissions. Files are atomically replaced with mode 0600 under process and file locks. The board survives service restarts and opt-out. Removal from Mesh disables access but preserves files. There is no cloud board database and no automated website login or cloud account synchronization.

Use **Export Specklet JSON**, then import the file through https://specklet.progretech.com/settings. Specklet uses IndexedDB in that browser. Its current importer merges new IDs and retains existing IDs, so importing a later snapshot into an already populated browser does not overwrite those existing tasks. Use a fresh workspace for a standalone historical snapshot, preserving a browser backup before clearing anything. To bring owner changes back, export from Specklet and upload to Mesh. Same-origin and owner checks plus exact host bindings apply; board content transits the authenticated relay temporarily. Browser rendering treats task text as data.

The Task Board supports scope/notes, priority, order and status edits, adding tasks, downloads, file uploads and a full editable JSON workspace. Stable project/task IDs preserve round trips. Imports reject malformed formats, duplicate IDs, invalid project references, invalid states and oversized content before replacing the file. A stale revision requires refresh and reconciliation, rather than silently overwriting newer work. Uploaded board text cannot authorize execution, tools or external messages.

`mesh_specklet` is a native agent tool bound to the runtime identity. It lists only that runtime's enabled, enrolled boards and uses the returned board ID and revision for updates. The prompt hook supplies up to 20 open tasks as advisory data when tracking is enabled. Agents consult the tool for the full board and save on every task status or scope change. Turn-off is checked inside the same lock as writes, so an already running agent cannot continue updating a disabled board through the tool. Model compliance with the tool instruction still requires live acceptance; prompt injection alone is not proof that every agent follows it.

Mesh request milestones and Factory office mission transitions save immediately when observed in the owning host process. A completed Mesh request is labeled as a request, not proof of verified task delivery. Native factory workday ledger metadata is observed every two seconds; intermediate states between published snapshots can be missed. `review`, `blocked`, `uncertain` and interrupted native jobs remain blocked pending review; successful process exit alone does not mark a native task done. Owner scope/status edits remain until a new source transition; unchanged observations do not undo them. Other runtimes need an adapter implementing these contracts.

Specklet supports `open`, `done`, and `cancelled`. Mesh stores `doing` and `blocked` under `meshStatus`, with compatible Specklet status `open`. If an owner changes the compatible status in Specklet, that status wins on import. This preserves visibility without modifying Specklet's source or duplicating its whole application. Boards accept up to 500 tasks, up to 256 KiB of task/workspace content and 512 KiB import payloads. Recent history retains 250 board mutations; exported owner snapshots provide longer-term history. Use the export instead of expecting unlimited host history.

MemPalace remains the independent durable context and teaching system. Board updates do not write memories, replace memory checkpoints, or automatically convert memories into tasks. A task can refer to a memory; a memory need not be a task. Git remains code truth and original factory ledgers remain execution evidence.

Release acceptance requires the Python and adapter suites, a real browser JSON round trip using Specklet's actual store, and owner-isolation/off-switch/conflict tests. Apply the same reviewed source to hosted and local Mesh and install the matching adapter/host extension. Production rollout and actual model/tool execution must be recorded separately from fixture acceptance.
