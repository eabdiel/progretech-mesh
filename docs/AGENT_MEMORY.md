# Agent memory search and release parity

Fleet tiles, the Factory inspector and each agent Control Center have **Memory search**. Open it and explicitly enable **Share this agent’s project memories with my Mesh fleet logins**. The per-agent grant is stored on the host. Both owner logins share the grant with their existing fleet access. Turn sharing off to revoke future searches. Removed enrollments cannot search.

The dialog searches active shared **project** records authored by the bound agent, in ProgreTech or Local-Workstation. It returns title, content, ID, author, provenance and date; long records are bounded. Other authors’ records, superseded/retracted records and all private agent memories are excluded. The host opens the existing canonical database read-only; a missing database stays missing and is reported unavailable. This grant does not enable another role to inspect private memories.

Hosted searches travel through the authenticated gateway temporarily. Search queries and results are not added to Mesh event buffers, chat history, browser storage or cloud databases. HTTP responses are no-store; closing the dialog clears its results. The database, sharing grant and search execution remain local. This is ephemeral relay, not a direct browser-to-host transport or an end-to-end encrypted protocol.

The installed local web service runs the same release checkout and UI as Cloud Run. It binds to loopback and accesses the host with its existing token internally; no cloud reconnect credential is copied. Local host trust is labeled as such, not claimed to be a CodeSeal enrollment. The local Factory and hosted Factory therefore control the same runtime state. The separate standalone desktop package also includes this dialog and can search explicitly imported OpenClaw roles when the authenticated local host is installed; unrelated runtimes report unavailable.

For each future Mesh release, run the complete tests including test_agent_memory.py, test_mesh_offline.py and test_release_parity.py, build/deploy Cloud Run from the reviewed commit, then run scripts/install-local-release.py from that same commit. Verify both /healthz versions/build IDs and shared asset hashes. Preserve the local service base unit, primary dirty checkout, host data and configuration. Standalone Windows/Linux installers use the same source/shared assets and require native platform builds; updating the local web service does not rebuild those installers.
