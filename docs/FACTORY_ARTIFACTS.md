# Factory attachments, deliverables and dependent work

Factory chat, mailbox messages and mission briefs accept up to three attachments, each up to 10 MB. Transfers use owner-scoped, same-origin management requests through the verified host. The host verifies ordered chunks, exact byte count and SHA-256 before issuing a local file reference. Inputs stay in a protected role-bound prompt-attachments directory; they are not automatically published as team outputs. Agents use their existing approved local file-reading tools; an upload receipt alone does not prove the model read it.

Open **Artifacts** to review generated files. Publish non-secret copies under `~/Rend/artifacts/<agent>/` (rend, lyra, mak, designer, reviewer, architect, progre, fast) or an existing job's `~/Rend/jobs/<job>/deliverables/`. Agent-labelled folders supply producer attribution; shared job deliverables explicitly say shared rather than inventing a producer. The browser lists bounded metadata, previews escaped text, downloads up to 10 MB and can insert a current artifact reference into the selected prompt. Symlinks, hidden/private/credential folders and common secret filenames are excluded. This is a shared published-file browser, not access to private runtime workspaces or MemPalace bodies.

For “Reviewer, when Designer delivers an icon, review it”, enter the instruction in Reviewer's chat and select **Wait for a new deliverable from Designer**. Queueing explicitly authorizes one follow-up. It waits for a new or changed published Designer artifact relative to its creation baseline, targets Reviewer's exact enrolled runtime, respects sleep/busy admission and records the input artifact plus result. Pause/resume/cancel apply before admission. After dispatch, native agent pause/sleep controls apply to its running activity. Host restarts mark interrupted admission unconfirmed; no automatic replay. Ordinary free-text chat alone is not a durable dependency rule. There is no claim of general natural-language workflow parsing.

New published artifacts and completed conditional follow-ups generate Director mailbox notices and are reviewable in the artifact browser/conditional queue. Publishing a file does not establish task completion. The Director reads mailbox notices during its next configured office mission; native Rend and the virtual office Director are distinct execution surfaces. File browsing remains available without CrewAI execution configured.

**Office chatter** is off by default. While enabled it runs serial two-agent conversations in repeating 15-minute sessions, with a short pause between pairs. Only awake agents with no native or Mesh work are admitted; owner requests take priority. Each turn checks CPU load, RAM/swap pressure, configured local models and available dedicated GPU telemetry. Admission is checked again under the shared inference lock before preloading. Missing telemetry defers chatter; it never evicts another model. These conservative checks reduce contention but cannot guarantee zero out-of-memory failures as other applications may allocate concurrently.

Drag one signed role node onto another while chatter is enabled to queue that exact pair. Positions remain pinned through refresh. The requested conversation line is labelled as requested until a real reply exists; click it to set the topic for the next turn. Empty topics select the established charter, artifact quality, memory learning or project maintenance themes. Already submitted turns retain their topic. Queued pairs wait for capacity or sleeping participants and are stopped when chatter is disabled. A currently running turn may finish; no forced cancellation or restart replay occurs.

Each turn includes at most two attributed shared ProgreTech project lessons by the participant or Codex, with bounded text and evidence references, plus change counts from established repositories. A service reader never assumes a role identity or reads private memories. Chatter authorization permits this host-side project context; per-agent cloud memory search remains separately opt-in. Retrieval status and memory IDs are visible with the conversation. Chatter uses separate native sessions, a bounded reply token budget, and discussion-only instructions. It is not permission to execute changes or evidence that agents learned. Normal native memory lifecycle records remain separate from reviewed technical checkpoints; failures must be shown honestly.
